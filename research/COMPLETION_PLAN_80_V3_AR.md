# خطة استكمال التقنيات الثمانين — الإصدار الثالث
التاريخ: 2026-10-20. النطاق: HazRob-Tank/research فقط. الفرع: `research/complete-g2-07-08-20261020`.

## الحالة الفعلية
اكتمل تدقيق أهلية المدخلات والأدلة الخارجية لـ80 معرفًا، وليس تنفيذ 80 خوارزمية كاملة أو اعتماد جهاز قياس. سجل G1 التاريخي: 80/80 نماذج أولية ناجحة برمجيًا و1261 حالة تاريخية. G2: 49 ذات تشغيل عددي/وصفي خارجي، 29 محجوبة عن الهدف المطلوب، 2 نظرية. G3 لجهاز Tank: 0/80. بعض ما يحمل أسماء CNN/GNN/XGBoost ما زال بدائل أولية؛ يُحظر ترقية حالته اعتمادًا على الاسم.

## ما أُنجز في هذه المتابعة
- G2-07 وG2-08: مصدر وكود واختبارات وتشغيل GitHub ناجح ونتائج أصلية محفوظة، مع تقارير العشر وتقسيم تدريب/معايرة/اختبار.
- إصلاح تقييم conformal ليحسب المجموعة الفارغة امتناعًا وإخفاق تغطية صحيحًا.
- جرد أربع مجموعات خارجية: UCI1081=90، UCI270=13910، UCI308=58، UCI309=180؛ الإجمالي 14238 تعرضًا. لا مضاعفة ملفات UCI309 المخفضة، ولا إضافة UCI224 المكرر.
- تصحيح دلالة بيانات UCI309 وUCI308، مع بقاء عدم التكافؤ مع حساسات Tank واضحًا.

## مسارات العمل التالية
1. **اكتمال التنفيذ:** عشر الأولوية الأولى أدناه، بحيث تصبح الخوارزمية المسماة حقيقية أو يظل الاسم مقيدًا صراحة بالبديل المنفذ. بيانات خارجية تكفي لاختبار البرامج والتدريب البحثي، ولا تؤجل هذه الأعمال بحجة غياب قياسات Tank.
2. **أهلية البيانات:** لكل معرف ناقص حدد حقلًا/تجربة/بروتوكولًا مطلوبًا؛ لا تساوِ بين «غير متاح لجهاز Tank» و«غير موجود في UCI مطلقًا». يمكن فتح تجربة خارجية جديدة بشرط وصف إعادة التعريف والوحدات بوضوح.
3. **التحقق المستقل:** تثبيت split/config قبل التشغيل؛ التدريب والاختيار في الجزء الداخلي فقط؛ تجميع فواصل عدم اليقين على مستوى التعرض أو الجلسة الملائمة، لا على النوافذ المرتبطة؛ حفظ نتائج كل محاولة وعدم انتقاء الإيجابي.
4. **تجارب Tank:** بيانات مقاومة وR0 وأطوار MQ7/MQ9 وBME ومرجع غاز موثق، وتعريضات تحقق مستقلة عبر الأيام والأجهزة. الحساسات الروبوتية تحتاج موضعًا وتوقيتًا وتأخرًا وحقيقة مكانية. تُجمع التجارب بترتيبات مختبرية مناسبة ويُحدد حجم العينة قبل الادعاء بالأداء وفق الهدف وعدم اليقين المطلوب؛ لا اختراع حد نجاح واحد لكل التقنيات.

- كل دفعة عشر معرفات؛ لكل معرف: كود، اختبار مرجعي، مصدر البيانات وحقوقه، وحدات، split، metrics، uncertainty، failure analysis، قرار قبول/رفض/نقص بيانات.
- بوابة G2 reviewed ليست G2 data-ready ولا G3 accepted. يظل `empirical_gate=NOT_VALIDATED` حتى دليل مستقل ملائم للجهاز والهدف.
- لا يوصف اختبار forward ثابت بأنه تدريب شبكة، ولا حساب معاملات بأنه profiling فعلي، ولا ترتيب نقاط بأنه أخذ عينات منفذ.
- التوثيق الآلي المفصل: `NEXT_ACTIONS_80.json`. سجل التشغيل والنتائج: `PROGRESS_80.json` و`BATCH_RESULTS_80.md`. نقطة الاستئناف في أعلى `RESUME.md`.
- في وجود تطوير متزامن على main: مراجعة الفروق ودمج PR دون استبدال سجلات أحدث. لا merge أو تعديل للإنتاج ضمن هذه المرحلة.
- لا ادعاء مطابقة ISO/IUPAC/IEC اعتمادًا على خطة أو threshold؛ يلزم اختيار وثيقة نافذة ملائمة للهدف وإثبات تحقق متطلباتها قبل ذكر المطابقة.
