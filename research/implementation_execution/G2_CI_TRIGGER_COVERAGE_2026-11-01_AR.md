# G2 — إغلاق فجوة تشغيل CI عند تغيير إيصالات المصدر والتوثيق (2026-11-01)

## المشكلة المثبتة
كان مسار GitHub Actions المسمى \`g2-signal-lineage-v4.yml\` يقيد أحداث \`push\` و\`pull_request\` بملفات Python محددة، وملفات JSON معدودة بالاسم، وبعض مسارات الأدلة الخام. لذلك كان تعديل ملف مثل \`G2_MQ4_FORWARD_DAY_RANKING_2026-11-01.json\` أو \`RESUME.md\` منفرداً لا يطابق مرشحات هذا المسار. نجاح CI على التزام تنفيذي سابق لا يثبت تلقائياً نجاحه على التزام توثيقي لاحق.

## الإصلاح
أُضيف النمط \`research/implementation_execution/**\` إلى مرشحات \`push\` و\`pull_request\` مع الإبقاء على مرشحات \`research/g2/raw/**\` و\`research/g2/evidence/**\` وسجل التقنيات الثمانين. بقي \`push\` محصوراً في فرع البحث \`research/chemcore80-central-evidence-gap-analysis-20261021\`. لم يتغير \`main\` أو Stable أو تطبيق Android أو الفريموير.

أُضيف \`test_g2_workflow_trigger_coverage.py\` بخمسة اختبارات انحدار: تغطية إيصالات JSON والتوثيق والملفات المتداخلة على الحدثين؛ كشف الفجوة عند حذف النمط العام؛ استمرار تغطية الأدلة الخام وسجل 80 تقنية؛ حصر الدفع في فرع البحث؛ والمحافظة على الاختبارات الكاملة وتدقيق الأدلة وبوابة النشر.

## حدود الاستدلال والتحقق
هذه اختبارات ثابتة لمرشحات YAML؛ **لا تحاكي خادم GitHub ولا تشهد بتشغيل فعلي**. يلزم فحص تشغيل Actions على الالتزام الجديد وتسجيل نتيجته. لا يتضمن التعديل بيانات تعرض جديدة أو معايرة مرجعية مستقلة أو اختباراً محجوباً على روبوت Tank؛ لذلك تبقى \`g2_pass_candidates=0\` و\`g2_blocked=80\` ولا يُمنح G2 أو G3.

لإعادة الإنتاج: \`python -m unittest discover -s research/implementation_execution -p 'test_g2_workflow_trigger_coverage.py' -v\`، ثم مراجعة تشغيل \`Tank V4 G2 — source signal and R0 evidence gate\` المرتبط مباشرة بالالتزام الجديد.
