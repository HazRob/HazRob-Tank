# بروتوكول استقبال التنبؤات المقترنة لبيانات MQ4 — بحث G2 فقط (2026-11-01)

## الغرض والنطاق
تعالج هذه الخطوة ثغرة منهجية: الملخص المرجعي المثبت يتضمن مصفوفات التباس مجمعة لخمسة نماذج على 14,186 قراءة، لكنه لا يقدم التنبؤات الخمسة المقترنة بكل معرف صف. ولذلك لا يمكن من المجاميع وحدها حساب اختلاف الأخطاء المرصود، أو اختبار McNemar، أو أداء دمج OR/AND الفعلي. الأداة `g2_mq4_paired_prediction_intake.py` **عقد استقبال وتدقيق**، وليست استرجاعاً لهذه الصفوف أو إثباتاً لتوافرها.

## ملف الإدخال المطلوب
ملف JSON ذي الجذر الكائني يتضمن:
- `schema = hazrob.g2.mq4-paired-predictions.v1` و`origin = EXTERNAL_SOURCE_RESEARCH_ONLY`.
- `source_summary_sha256`: بصمة SHA256 لملخص المكتبة المركزي المثبت، لا لبصمة ملف مُنشأ حديثاً.
- `rows`: صفوف فعلية، لكل منها `row_id` فريد؛ `raw_row_sha256` بصيغة 64 رقماً سداسياً صغيراً؛ `test_day` و`fold_test_day` متطابقان؛ `train_days` قائمة أيام التدريب؛ `reference_positive_4ppm` منطقية؛ `predicted_positive_4ppm` يحوي القيم المنطقية للنماذج الخمسة المحددة دون زيادة أو نقصان.

لا يجوز توليد قيم `raw_row_sha256` افتراضية لصفوف المصدر الحقيقي. لا تثبت سلامة صيغة البصمة أن الصف مطابق للأرشيف الخام؛ تتطلب المطابقة المستقلة إتاحة الأرشيف الأصلي ومعرفات صفوفه وتوثيق آلية تكوين البصمات.

## بوابات الرفض
ترفض الأداة مفاتيح JSON المكررة والقيم غير المنتهية، ونقص الصفوف، وتكرار المعرفات، واختلاف يوم الاختبار عن يوم الطية، وتداخل يوم التدريب مع الاختبار، وعدم اتساق مجموعة أيام التدريب بين صفوف يوم اختبار واحد، وغياب نموذج، واستخدام أعداد مكان القيم المنطقية، واختلاف بصمة ملخص المصدر أو نطاقه، وأي سجل أدلة فيزيائية مستقلة غير متحقق منه.

عند تشغيل CLI بوضعه الافتراضي تشترط الأداة **14,186 صفاً، و11 يوم اختبار، و2,346 مرجعاً موجباً و11,840 سالباً**، وتطابق مصفوفات الالتباس للنماذج الخمسة مع المصدر المثبت. يظل وضع `require_full=False` للاختبارات الاصطناعية البرمجية فقط؛ لا يتاح كخيار CLI للإنتاج.

## التمييز بين الاتساق والاعتماد
تحسب الأداة مصفوفات الالتباس وتكرارات التوافق/الاختلاف المقترنة **داخل الملف المقدم**، وتكشف أيام الاختبار التي استُخدمت فيها أيام تدريب لاحقة. حتى عند اجتياز التحقق العددي، تبقى حقول `original_raw_archive_row_hashes_independently_verified` و`paired_inferential_test_authorized` و`g2_qualified` و`g3_qualified` جميعها `false`. السبب: الملف الذاتي لا يثبت مصدر الصفوف، ولا استقلال التعرضات، ولا التحقق الفيزيائي المرجعي، ولا الصلاحية المستقبلية.

عتبة 4 ppm تشخيصية من الدراسة الأصلية، وليست حداً مهنياً للسلامة. المصدر الأصلي استعادي، وتستخدم 10 طيات من 11 تدريباً على أيام لاحقة؛ لا يجوز تفسيره كاختبار مستقبلي أو اختبار دقة الروبوت.

## إعادة الإنتاج
بعد الحصول على ملف التنبؤات الحقيقي الموثق:
```bash
python research/implementation_execution/g2_mq4_paired_prediction_intake.py \
  --input /path/to/verified_source_predictions.json \
  --output /tmp/g2_mq4_paired_intake_audit.json
python -m unittest discover -s research/implementation_execution -p 'test_g2_mq4_paired_prediction_intake.py' -v
```
الاختبارات الحالية اصطناعية فقط وتختبر قواعد الرفض والحساب؛ لا تحتوي على بيانات غازية جديدة ولا تمثل تحققاً علمياً.

## ما يلزم قبل الترقية
1. استخراج تنبؤات كل نموذج لكل صف من مصدر MQ4 الخام مع معرفات أصلية وآلية بصمات قابلة للتدقيق.
2. إعادة توليد مصفوفات الالتباس ومطابقتها، وفصل النتائج الاستعادية عن اختبار مستقبلي محجوب.
3. تجارب تعرض فيزيائية مستقلة للروبوت، ومعايرة مرجعية قابلة للتتبع، وتقسيمات محجوبة على مستوى التعرض والجهاز والجلسة.
4. مراجعة مستقلة للأدلة قبل أي تغيير في حالة التقنيات الثمانين أو ChemCore Stable.

**الحالة:** `g2_pass_candidates=0`، `g2_blocked=80`، `source_blocked=14`؛ سجل الأدلة المستقلة `records=[]`. لا اعتماد G2/G3.
