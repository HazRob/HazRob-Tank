# V9 الدفعة الأولى — دراسة جدوى أولية قبل اعتماد وتنفيذ التعديلات

**تاريخ المراجعة:** 2026-11-06  
**حالة الوثيقة:** REVIEW_ONLY / لا تغييرات على مصادر Android أو ESP32، ولا تشغيل بناء.  
**مرجع الكود:** `feature/tank-v9-implementation` المشتق من V8 عند افتتاحه.

## خط الأساس المثبت من المصدر

- ESP32 `Config.h`: `SDA=21, SCL=22` لـ ADS1115 عند 0x48/0x49؛ `ENV_SDA=13, ENV_SCL=14` لـ BME/BMP؛ قيادة مستمرة يسار GPIO16 ويمين GPIO17 بموجات LEDC 50Hz؛ إنذار GPIO26 لكن `ALERT_OUTPUT_INSTALLED=false`.
- `Hardware.cpp`: الحساس الضوئي الحالي LM393 على GPIO34 هو عتبة رقمية لا تقيس Lux؛ `lightJson()` يصرح `quantitative_lux=false`؛ محركا القيادة مرتبطان بدارة توقف مهلة 500ms. إعادة ضبط ناقل BME المخصص لا تؤثر حاليًا على ناقل ADS.
- Android `MainActivity.showTab()` يطلب فتح المطور عند اختيار تبويب المطور؛ `DeveloperTab.renderLocked()` يُظهر أيضًا زر «دخول المطور»، والبوابة `askPin()` تُطلق نافذة كلمة مرور. يجب اختبار المسار المكرر وتصحيحه مع الإبقاء على باب تحقق واحد.
- `/data` و`/diag` و`/cfg` و`/drive` الحالية هي عقود تحتاج توسعة متزامنة، من دون حذف حقول الإصدار السابق قبل التوافق.

## خريطة عناوين I2C المقترحة — مشروطة بتحديد موديل الحساس الضوئي وتأكيد BMS

| الجهاز | العنوان المتوقع | وضعه الحالي |
|---|---|---|
| ADS1115 1 | 0x48 | Wire(GPIO21/22) |
| ADS1115 2 | 0x49 | Wire(GPIO21/22) |
| PCA9685 | 0x40 | جديد |
| MPU-6050 | 0x68 أو 0x69 | جديد |
| BH1750 (إذا كان هذا موديل الضوء) | 0x23 أو 0x5C | موديل غير مؤكد |
| BME280/BMP280 (إذا كان المقصود) | 0x76 أو 0x77 | EnvWire(GPIO13/14) حاليًا |

**مخاطر الناقل الموحد:** الضوضاء وطول الأسلاك؛ pull-ups مكافئة؛ أي Pull-up إلى 5V خطر على GPIO ESP32؛ تأخير ADS بسبب زيادة معاملات I2C؛ انهيار حافلة I2C واحدة قد يؤثر في التحليل والقيادة. نحتاج اختبارات fault injection وشروط فصل أو تعطيل آمن للقوة المحركة. لا يُسند التحكم السلامي إلى تطبيق الهاتف وحده.

## خريطة PCA9685 مقترحة مبدئيًا — ليست تعيينًا نهائيًا

| القناة | الوظيفة |
|---|---|
| 0 | قيادة يسار |
| 1 | قيادة يمين |
| 2 | الفك (سيرفو) |
| 3 | محور الذراع A |
| 4 | محور الذراع B — مشروط بوجود سيرفو فعلي |
| 5 | قاعدة الذراع — مشروط بتأكيد المحرك |
| 6 | الشفاط ON/OFF عبر مفتاح قدرة |
| 7 | المضخة ON/OFF عبر مفتاح قدرة |
| 8 | المروحة ON/OFF عبر مفتاح قدرة |
| 9 | الإطفاء ON/OFF عبر واجهة مناسبة للحمل |
| 10 | الإضاءة الليلية ON/OFF عبر مفتاح قدرة |
| 11 | إضاءة الذراع ON/OFF عبر مفتاح قدرة |
| 12 | الإضاءة التحذيرية ON/OFF عبر مفتاح قدرة |
| 13 | قناة إضاءة رابعة محجوزة غير مسماة |
| 14–15 | احتياط |

**الملاحظة الكهربائية:** الـ PCA9685 16 خرج تحكم منطقي بتيار منخفض مع تردد PWM مشترك للـ 16 قناة. يمكن إبقاء التردد ملائمًا للسيرفو واستخدام 0%/100% لمفاتيح ON/OFF، بشرط تصميم مراحل القدرة والتحقق من حالات التمهيد والانقطاع. تغذية `VCC` المنطقية للوحة مختلفة عن `V+` الخاص بالسيرفو، ولا يتغذى حمل DC من مخارج PWM. يلزم قفل أمان للمحركات ولو تعطلت أو تجمدت حافلة I2C.

## منهج تنفيذ التوافق بعد المناقشة والموافقة

1. اعتماد المنافذ والطرز والعدد ومصادر القدرة والسلوك الآمن.
2. تعريف حقول بيانات V9 وعقد `/data` و`/diag` و`/cfg` وأوامر الذراع والمساعدات، مع المحافظة على الموجود والتوافق مع التطبيق.
3. تنفيذ ESP32 أولاً في فرع V9 مع اختبارات بناء وسلامة، ثم Android المتوافق، ثم تكامل الطرفين وبيانات التخزين والتقارير.
4. عدم تصنيف التعديل `DONE` قبل إثبات الاختبارات المطلوبة؛ لا تُعلن دقة ميل أو انبعاثات أو استقرار I2C بدون تجارب فعلية.

## مسائل حاسمة للمناقشة، بالترتيب

1. هل تكون أولوية MPU6050 للتحذير من الانقلاب على بدن الروبوت أم قياس حركة الذراع؟ لتحقيق الاثنين بدقة مستقلة يُفضَّل حساسان.
2. تحديد العدد الحقيقي للسيرفوهات الصغيرة وأسماء مفاصل الذراع وطراز محرك القاعدة، والقيود الميكانيكية.
3. رقم وحدة Lux وطريقة وصلها، نوع البازر، هوية «BMS»، والفولتية/التيار للأحمال.
4. مدى قبول المستخدم لمفتاح قدرة خارجي لكل حمل واشتراطات وقف الحركة الآمنة.
