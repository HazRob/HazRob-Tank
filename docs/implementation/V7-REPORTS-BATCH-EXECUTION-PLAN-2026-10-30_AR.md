## 1. قرار تغيير المنهجية
بعد اعتماد قواعد التصميم G01–G18 وبدء تنفيذ النموذج الأول R01، اقترح المالك أن تُناقش **جميع التقارير الستة منفردة ويُوثَّق ويُعتمد تصميم كل منها**، ثم **تُنفذ التعديلات الإنتاجية في مرحلة موحدة بعد إغلاق المناقشات** بدل تكرار بناء النمط المشترك ست مرات.

**الطريقة المتبناة:** `DISCUSS-ALL → FREEZE-ALL-SPECS → BUILD-SHARED-ONCE → IMPLEMENT-SIX → TEST-EACH → INTEGRATE → SIGN-OFF`.

- **ما يبقى منفردًا:** فحص تقرير R01 ثم R02 ثم R03 ثم R04 ثم R05 ثم R06، وتوثيق قائمة مشكلات كل منها، وخريطة البيانات والمخططات، والبدائل والقرارات والموافقة الخاصة به.
- **ما ينفذ مرة واحدة:** الثيم وهوية الألوان، الشعار، رأس وتذييل الصفحات، تباعد 1.15، حشوة الخلايا 2×1 مم، منظومة خطوط ≥12pt، العربية وBidi، الترقيم، تقسيم الصفحات، أدوات الرسم الأساسية، مواءمة مخارج المحركات مع PDF.
- **ما ينفذ لكل تقرير في مرحلة واحدة:** مولّدات R01–R06 أو محولات البيانات المناسبة لها، مع معالجة الحالات الناقصة بدون اختراع قياسات ولا إضافة شروط تحليلية ثانية خارج المحركات.
- **ما يُختبر باستقلال:** كل تقرير على بيانات اصطناعية واضحة وعينات أصلية متاحة؛ صفحات قصيرة وطويلة وحالات Null، ثم ربط التقرير بالإدخال الحقيقي في التطبيق.
- **ما يُختبر كتطبيق متكامل:** مقارنة PDF↔Engine JSON↔SQLite/XLSX، خطوط A4 12pt، لون Header/Footer، تشكل العربية، صلاحية الصفحات والملفات، وفتح ومشاركة التقارير من Android. لا اعتماد APK إلا بإذن.

## 2. حالة R01 عند الانتقال
**لا يُهدر تنفيذ R01 الذي بدأ قبل تعديل الاستراتيجية.** تم إنشاء `TankInstantV7PdfWriter.java`، وتوجيه التصدير الآني إليه، وإضافة مورد الشعار الرسمي ومخططي `Evidence Calibration Matrix` و`Radar`. اختبار GitHub Actions `41134485012` أثبت بناء Android وإنتاج PDF أصلي صالح مع تحليل أحجام الخطوط والترويسة، ثم أجريت تنقيحات لتوزيع Radar والتسميات في commits لاحقة.

- يُعامل R01 منذ الآن **نموذجًا أوليًا مجمد المتطلبات**، وليس حزمة نهائية يفرض تصميمها على بقية التقارير.
- لا تستمر إعادة برمجته استجابةً لقرارات جزئية متغيرة؛ يُستخدم لتقييم المكونات القابلة لإعادة الاستخدام ضمن مرحلة العمارة المشتركة.
- **الاختبار الناجح السابق لا يغلق تقرير R01** إذا عُدّلت الشيفرة بعده، حتى تمر النسخة النهائية باختبار جديد وتقييم بصري.
- لا يُبدّل هذا المسار Firmware V6 أو قواعد G3/معايرات R0 أو ChemCore؛ الشرط الوحيد هو مطابقة العرض لمخرجات المحرك لا إعادة التحليل داخل PDF.

## 4. مفاضلة كفاءة التنفيذ
**المكاسب:** تعريف الثيم مرة واحدة؛ منع اختلاف رؤوس الجداول واللوجو والخطوط؛ إعادة استخدام عدادات ومصفوفات ورسوم تدفق؛ تقليل إعادة التصحيح والتكرار في Gradle/CI؛ وضوح اعتماد المالك قبل تكوين APK.
